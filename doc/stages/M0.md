# 阶段 M0 · 基座收口

> 分支：`stage/m0`  |  开始：2026-11-04  |  状态：🔨 进行中
> 上游：[ROADMAP](../ROADMAP.md) §三 M0  |  规格：[COMBAT_SPEC](../COMBAT_SPEC.md) §八

## 1. 目标

**在动任何玩法之前，先让"每一批都能被复核"。**

一句话：*没有断言、没有独立试玩场景、没有截图，"验收"就只能靠你反复试玩——那是不可持续的方式。*

## 2. 效果（做完之后会有什么不同）

1. **一条命令跑完机制断言**，全绿/全红一目了然，不需要你打 100 遍来验证一条规则；
2. **F5 直接进试玩场景**（`arena_01`），不再进调试用的测试场景；
3. **我能给你改前/改后的截图对比**，而不是让你自己开来看；
4. 从这一阶段起，每个阶段都能**独立回滚 + 回归**（`stage/mN` 分支 + tag）。

> 这一阶段**不改变任何手感、数值、玩法**。你的三分钟验收只要一句"没退化"。

## 3. 范围

### In

| # | 工单 | 产出 |
|---|------|------|
| 1 | `tests/` 框架 + 3 条基础断言 | 一条 headless 命令跑完，退出码 0/1 |
| 2 | 场景分离：`scenes/arena/arena_01.tscn`（试玩）与 `test_scene_enemy_attack.tscn`（调试沙盒） | main scene 指向 arena |
| 3 | 截图自动化 | 一条命令出运行截图 PNG |
| 4 | 阶段文档 / 分支 / tag 流程落地 | 本文档 + `stage/m0` |

### Out（为什么不做）

| 不做 | 为什么 |
|------|--------|
| 任何数值/玩法改动（解围、HP、气、相机） | 属于 M1；本阶段动它们就失去"基线"的意义 |
| 敌人第二招、格挡 | M2 |
| 重构（MoveRunner / Health / 命名空间） | M4 前才需要 |
| 美术 / 音效 | M7 |

## 4. 验收标准

### L1 · 自动断言（headless，一条命令）

| # | 断言 | 通过条件 |
|---|------|---------|
| A1 | 玩家攻击不会命中自己 | 玩家 Hitbox 的 mask 与自身 Hurtbox 的 layer 不相交（构造断言） |
| A2 | 双向命中 | 玩家能打死敌人；敌人能打伤玩家（各跑一次脚本，断言血量变化） |
| A3 | 基线记录 | 记录"当前 50 HP 敌人的击杀耗时"，作为 M1 的对照基线（**只记录，不断言**） |

> A3 是"回归对照"，不是"通过条件"——它的作用是让 M1 的数值改动有可比对象。

### L2 · 手感（人打三分钟）

- 只有一句：**"有没有退化"**。
- 具体看：移动/跳跃是否照旧、jab/heavy 是否照旧出、闪避是否照旧、命中是否有顿帧与震屏。
- **通过线：没有明显退化。**

### L3 · 外部验证

- 本阶段不需要。

## 6. 风险与回滚

| 风险 | 处理 |
|------|------|
| headless + C# 的运行时行为与带窗口时不同（例如相机为 null） | 现有代码已判空；断言只依赖节点/数值，不依赖渲染 |
| 分离场景时 main scene 的 uid 写错 | 用 `godot_set_project_setting` 或直接改 project.godot，跑一次验证 |
| 截图在无显示环境失败 | 已在本机验证可行（Metal / Forward+）；失败则降级为"仅 headless 断言"并记录 |
| 本阶段引入回归 | 本阶段不改玩法，理论上零风险；真出问题直接 `git checkout main` |
