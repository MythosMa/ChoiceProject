# 阶段 M2 · 三个问题

> 分支：`stage/m2`  |  开始：2026-11-05  |  状态：🔨 进行中（**2B-1 ✅ / 2B-2 ✅ / 2B-3 ✅，待 L2**）
> 上游：[ROADMAP](../ROADMAP.md) §三 M2　|　规格：[COMBAT_SPEC](../COMBAT_SPEC.md) §1.4 / §4.4

---

## 1. 目标

**从"一个免费解"变成"一局要判断两三次"。**

M1 解决了"敌人没有回合"；M1 结束时的问题是：**敌人只有一张牌，打久了像节拍器**。
M2 要做的是让敌人有**两张牌**，让玩家从"预判它什么时候出"变成"预判它出哪一张"。

## 2. 效果（做完之后会有什么不同）

1. 敌人有两招，**tell 不一样、应对也不一样**；
2. 玩家有**格挡**这个新选项——但格挡不是白拿的（耗气 + 会被破）；
3. 一局里会出现 **2–3 次"必须做判断"的时刻**，而不是一路按住某个键。

## 3. 范围

### In

| # | 内容 | 说明 |
|---|------|------|
| 1 | **敌人第二招** | 与直拳形成对照：一招"慢但可挡"，一招"快但破防" |
| 2 | **敌人选招** | 按距离/状态加权随机，不是固定顺序；两招共用同一套 tell 语言 |
| 3 | **玩家格挡** | 按住进入格挡态：减伤 90%、无硬直、**持续耗气**；气空自动解除 |
| 4 | **破防** | 第二招能打破格挡 → 格挡者进入大硬直（被确反） |
| 5 | HUD | 格挡态、气耗的可视反馈 |
| 6 | 断言 | A14–A17（见下） |

> **格挡与破防必须成对出现。** 只做格挡，玩家会按着不动；只做破防，格挡没人用。

### Out（为什么不做）

| 不做 | 为什么 |
|------|--------|
| 第三招 | 两张牌已经足够验证"读哪一张"；三张会先爆炸的是提示系统 |
| 上下段 | 需要纵向判定/跳跃攻击，属于 M4 之后 |
| 敌人第三阶段 / Boss | M5 |
| 玩家第三/第四招 | 现有 jab/heavy 在 M1 已能形成非对称赌注 |

### L2 · 手感（你打三分钟）

1. 我能不能**一眼分出**它这次出的是哪一招？

3. 我有没有因为"挡错招"吃过大亏？

**通过线：3 条里至少 2 条"是"，且能说出两招的区别。**

## 6.6 平衡：用断言替代手感（2026-11-05）

用户："现在玩起来有点复杂了，我也不好判断。"

于是停止凭手感调参，先写**设计目标断言**：

> **A20：无脑连打（不闪不挡，只攻击）不能赢。**

第一次跑出三种打法的真实数据：

| 无脑打法 | 结果 |
|---|---|
| 单招 jab | 玩家 0 / 敌人 60 → 输 |
| 交替 jab/重拳 | 玩家 0 / 敌人 60 → 输 |
| **重拳为主** | 玩家 **58** / 敌人 0 → **赢（免费解）** |

**根因（结构性，不是数值）**：识破的霸体只在敌人的 Startup/Active/Recovery 生效，
而且 `EnterPhase(Idle)` 会把预判清掉——**"被识破"只在它出招时成立**。
玩家只要等它收招、在待机窗口里打，就完全不受读招约束。

修法：预判在待机期保留（`greedWindowFrames = 120` 过期），待机时同样能让那一招打空。

结果（未改任何伤害数值）：

| 打法 | 改后 |
|---|---|
| 单招 jab | 玩家 0 / 敌人 180 |
| 交替 jab/重拳 | 玩家 0 / 敌人 180 |
| 重拳为主 | 玩家 0 / 敌人 24 |

> **教训：让玩家"能靠血量淹死"的不是伤害太低，是防御机制在时间上有洞。**
> 先把洞补上，再谈数值。

## 6.7 回归：连续扑空踉跄（2026-11-05）

用户实测："敌人会一直扑空"——连续 7 次 `敌人扑空踉跄！`，每次都是白送 ×3。

**这是我上一处修复的连锁反应**：
预判改成存活 2 秒之后，踉跄条件 `_predictedMoveId != null && 打空` 就等于
"这 2 秒内它**任何**一次攻击打空都算踉跄"。玩家一直躲，它就一直白送。

修法：踉跄要求 `_currentMove == counterMove`——**只有识破后的那一记反击打空才算**。
普通攻击打空只是空招，不给奖励。

> **教训：改时序（预判存活多久）会连带改变所有"看预判"的分支。**
> 这次改了 1 处，漏看了 1 处。以后动 `_predictedMoveId` 的生命周期，
> 必须把所有读它的地方列出来过一遍。

## 6.8 手感修复：闪避方向反了（2026-11-05）

用户："按住左、按闪避，实际向右冲了。"

根因：闪避用的是 `player.facing`（上次朝向），而 `facing` 只在 `moveAxis != 0` 时更新，
**闪避期间 moveAxis 恒为 0**，所以"按住左 + 闪避"的同一帧里 facing 还是上一次的朝向。

修法：`DodgeHandler.Enter()` 直接读**按下瞬间的输入方向**（按住左/右），没有再回退到 facing，
并把 facing 同步过去。

新增断言 **A21**：按住左闪避必须向左（实测 -112.5px），按住右必须向右（+112.5px）。

## 6.9 大确反（踉跄 ×3）的入口（2026-11-05）

用户问："大确反怎么触发？感觉触发不出来了。"

两套东西要分清：

| | 触发条件 | 倍率 |
|---|---|---|
| **确反 ×2** | 在敌人**后摇**里打中它，且**它那一招打空了** | ×2 |
| **大确反（踉跄）** | 敌人打出**承诺招**（识破反击 / 解围）并落空 → 踉跄 30 帧 | ×3 |

**为什么"触发不出来"**：为了修"一直扑空白送 ×3"，我把踉跄收成了"只有识破反击打空"；
但玩家为了躲识破会**交替用招**，于是永远不触发识破 → 永远见不到踉跄。从一个极端跳到另一个。

**定稿**：承诺招（识破反击 **或** 解围）打空 → 踉跄。普通直拳打空不算。

**实测发现（重要）**：入口**只能用 jab 骗**。
重拳不可闪避取消，两记重拳打完人还在后摇里，根本闪不出去——因此"两记重拳骗反击"物理上不存在。
jab 可闪避取消，第二记命中后立刻闪避（约 18–22 帧后）刚好盖住反击判定期。

新增断言 **A22**：5 个闪避时机里 3 个能让敌人踉跄。
