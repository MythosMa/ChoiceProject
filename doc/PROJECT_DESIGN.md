# Choice Project - 立项设计文档

> 版本：v0.1  |  日期：2026-08-01  |  状态：原型验证阶段

---

## 一、项目愿景

在一个类银河城（Metroidvania）的世界中，融入格斗游戏式的"择"作为核心战斗体验。玩家不只是在按键，而是在每一次交手中做出有风险的判断——读对了、押对了，就有高回报。

**一句话概括：** 在银河城里，玩街霸的"择"。

### 参考作品与分析

| 作品 | 借鉴点 | 需要警惕的点 |
|------|--------|-------------|
| 九日（Nine Sols） | 格挡系统贯穿始终、贴符的资源管理、机关与核心系统的联动 | 跑图时格挡深度有限，更多是"习惯"而非"博弈" |
| 空洞骑士（Hollow Knight） | 世界氛围、碎片化叙事、探索驱动 | 跳跳乐与战斗节奏偶有割裂 |
| 恶魔城（Castlevania） | 银河城结构范式、成长回溯 | 战斗系统相对简单，不是核心卖点 |
| DNF | 搓招系统在横版中的成功实践 | 是清版ACT而非银河城，关卡结构完全不同 |
| 街霸（Street Fighter） | "择"的灵魂——读对手、风险判断、确认反击 | 1v1结构，无法直接套用到探索型游戏 |

## 二、核心玩法定义："择"

### 2.1 什么是"择"

"择"不是广义的"做选择"，而是**战斗动作层面的即时判断**——在当前局面下，我应该搓出哪套连招、用哪个招式回应？

它和格斗游戏的"择"同源：读对手的动作 → 在极短时间内选择应对方案 → 选对了有高回报，选错了要承担风险。

### 2.2 "择"与现有系统的区别

| 对比维度 | 九日的格挡 | 本项目的"择" |
|---------|-----------|-------------|
| 核心考验 | 时机判断（二元：对/错） | 方案选择（多元：A/B/C哪个最优） |
| 快感来源 | "我接住了"的本能爽感 | "我读对了，选了最优解"的智力快感 |
| 深度上限 | 受限于时机精度 | 受限于选项丰富度和敌人行为复杂度 |
| 设计难度 | 较低（二值判定） | 较高（多元平衡，不能有永远最优解） |

### 2.3 "择"在不同场景中的表现

**对小怪（轻度）：** 简单的择，1-2个选项，快速解决，不拖节奏。
**对精英/Boss（重度）：** 深度博弈，敌人会"出题"，选项多、窗口短、回报高。
**对机关（中度）：** 择从战斗延伸到世界交互，作为节奏变化器存在。

## 三、战斗系统设计

### 3.1 连招与招式结构

角色的招式系统围绕"出招选择"构建，而非"搓招执行"。重点不在于手指能不能搓出来，而在于该不该选这一招。

**基础招式层（快速出招，不锁定移动）：**
- 方向键 + 攻击键，快速释放单段招式
- 例如：下+攻击 = 下劈，前+攻击 = 突刺，上+攻击 = 升龙
- 用于日常跑图、小怪战，不中断移动节奏

**连段层（状态切换，短暂锁定移动）：**
- 通过连续输入触发多段连招
- 一旦开始连段，角色进入"战斗状态"，方向键变为连招输入
- 连段中可"变招"——中途cancel当前连段，切换到另一套连招
- 用于精英怪、Boss战，是"择"的主要发生场景

**大招层（蓄力释放，高风险高回报）：**
- 需要消耗积攒的资源（气槽/能量）
- 释放前有蓄力动作，有被中断的风险
- 命中后收益巨大，空了就血亏

### 3.2 "择"的三个层次

**第一层：确反择（读招回应）**
敌人出招后露出特定破绽，玩家需要在短暂窗口内选择对应的连招进行确反。不同破绽对应不同最优连招，选对了伤害翻倍，选错了只有普通伤害或被反打。

**第二层：押注择（资源博弈）**
玩家需要决定是否消耗资源释放大招。敌人行为有规律但也有随机性，"押对"敌人接下来的行动窗口，大招才能命中。这层考验的是风险评估——值不值得把资源押在这一波上。

**第三层：变招择（流动应变）**
连段进行中，敌人突然变招（切换姿态、蓄力反击、暴露新破绽），玩家需要在连招途中判断：继续打完（安全但收益一般）还是中途变招（抓新窗口，高风险高回报）。

### 3.3 资源系统

- **气槽（能量）：** 通过连招命中、成功确反来积攒，用于释放大招和变招
- **血量：** 传统的生存资源
- 资源管理本身也是一种"择"——我现在把气用了，后面Boss第二阶段怎么办？

## 四、输入系统设计

### 4.1 核心矛盾

格斗游戏中方向键纯粹服务于搓招（角色朝向固定），银河城中方向键承担移动职责。两者在同一输入通道上产生冲突。

### 4.2 解决方案：混合输入仲裁

```
输入信号
  │
  ├── 空闲状态 → 方向键 = 移动
  │
  ├── 攻击按下 → 进入战斗状态
  │     ├── 方向键 = 招式输入（下劈/突刺/升龙等）
  │     └── 攻击结束后 → 回到空闲状态
  │
  └── 连段触发 → 进入连段状态
        ├── 方向键 = 连段路由输入
        ├── 移动暂时锁定
        ├── 可通过特定操作cancel退出连段状态
        └── 连段结束/cancel → 回到空闲状态
```

### 4.3 手感调校要点

- **输入缓冲（Input Buffer）：** 允许在动作结束前预输入下一个指令，保证连段流畅
- **状态切换宽容度：** 从移动到战斗状态的切换不能太敏感（误触），也不能太迟钝（不跟手）
- **Cancel窗口：** 连段中的变招窗口需要精确到帧级别，是手感的核心参数
- **移动取消后摇：** 某些招式的收招硬直可以通过移动来取消，保持跑图流畅

### 4.4 技术实现注意

- Godot 的 `_input()` 和 `_unhandled_input()` 的优先级需要规划好
- 建议实现一个独立的 InputManager 节点，统一管理输入状态机
- 输入缓冲帧数、状态切换延迟等参数应做成可调配置（Resource/Config文件），方便快速迭代

## 五、机关设计

机关是"择"从战斗延伸到世界交互的载体，作为跑图过程中的节奏变化器。数量要克制，整张地图预计10个左右。

### 方案A：喂招型（考反应和读招）

机关激活后，在特定时间窗口内释放某种信号（能量束轨迹、冲撞方向、暴露弱点位置），玩家需要在瞬间判断"我该用哪套连招回应"。

- 判对了：机关解锁，获得奖励/捷径
- 判错了：吃伤害或触发陷阱，但机关还在，可以再试
- 本质：格斗游戏里"对方出了站中拳，我用什么确反"

### 方案B：押注型（考风险判断）

机关要求蓄力释放大招激活，需要消耗积攒的资源。但机关有真有假——有些是真机关，投入就开；有些是陷阱机关，投入打水漂。

- 判断依据：机关外观差异、区域难度暗示、附近发现的信息线索
- 本质：格斗游戏里"这波要不要交超杀"

### 方案C：变招型（考流动应变）

玩家与机关交手过程中，机关会在连招途中突然变招（切换状态、暴露新窗口），玩家需要在连招中途判断：继续打完还是变招抓窗口。

- 本质：格斗游戏里的"确认"和"cancel"
- 变体：可以设计需要连续变招多次的复杂机关，作为后期高难度挑战

### 设计原则

- 三种类型交替出现，避免重复感
- 前期单一类型，后期可混合（如先喂招再押注）
- 每次机关的视觉包装要不同，即使底层逻辑相同
- 机关不是解谜主体，是节奏点缀，不能让玩家觉得"怎么又来"

## 六、敌人设计原则

"择"要有意义，敌人必须能"出题"。一个敌人出一种题，如果全游戏只有一种出题方式，第二次遇到就不需要择了。

### 6.1 敌人分类（Demo阶段）

| 类型 | 出题方式 | 考验的择 | 数量 |
|------|---------|---------|------|
| 直球型 | 明显的前摇攻击，破绽固定 | 确反择（基础） | 1-2种 |
| 多段型 | 连续攻击，最后一段才有大破绽 | 押注择（忍到最后还是中途打断） | 1种 |
| 变招型 | 攻击过程中会切换模式 | 变招择（连段中途应变） | 1种 |
| Boss | 综合运用以上所有 | 全部三个层次 | 1个 |

### 6.2 敌人AI设计要点

- 敌人的行为需要有"可读取的信号"——出招前必须有视觉预兆
- 但预兆不能太明显，否则变成无脑操作
- 敌人行为应有一定随机性，让"择"保持不确定感
- 敌人的"出题"节奏应该有变化，不能每次都一样

### 6.3 核心检验标准

> 玩家面对一个敌人时，脑子里转的念头应该是："它下一招是什么？我该用哪套连招？我敢不敢赌？"
> 如果玩家不需要思考就能打过，这个敌人的"择"就失败了。

## 七、美术策略（Demo阶段）

### 7.1 角色与敌人

- 使用色块/几何体拼接，不需要正式动画
- 角色：一个色块人形轮廓即可
- 敌人：不同形状和颜色的色块，通过形状差异快速区分敌人类型

### 7.2 不可省略的视觉要素

**敌人出招预兆（信息传达）：**
- 颜色变化（如变红表示即将攻击）
- 形状缩放（蓄力膨胀）
- 方向箭头/指示线的闪烁
- 这是"择"系统的信息基础，必须清晰可读

**打击反馈（满足感）：**
- 击中顿帧（hitstop）
- 屏幕震动
- 受击位移
- 击中音效
- 这些决定了"择对了"的快感

**输入反馈（确认感）：**
- 色块变色/发光
- 拖影效果
- 招式释放时的视觉爆发
- 让玩家确认"我搓出来了"

### 7.3 后期美术方向（Demo验证通过后）

- 方向待定，待核心玩法验证后再决定
- 候选：像素动画、骨骼动画（Spine/DragonBones）、手绘风格
- 世界观和故事在核心玩法验证后再展开

## 八、技术选型

| 项目 | 选择 | 说明 |
|------|------|------|
| 引擎 | Godot 4.x | 轻量、开源、适合独立开发 |
| 编程语言 | C# | 类型安全，适合复杂状态机管理 |
| 版本控制 | Git | 待定（LFS是否需要取决于后期美术） |
| 动画方案（Demo） | 代码驱动的色块变换 | 快速迭代，不依赖美术资源 |
| 动画方案（后期） | 待定 | 骨骼动画或逐帧像素 |

### 关键技术模块

- **InputManager：** 输入状态机，管理移动/战斗/连段状态的切换和缓冲
- **CombatSystem：** 连招路由、伤害计算、确反判定
- **EnemyAI：** 敌人行为状态机、出题逻辑、可读取信号系统
- **FeedbackSystem：** 顿帧、震屏、击中特效的统一管理
- **MechanismSystem：** 机关系统，支持三种机关类型的配置化实现

## 九、Demo范围定义

### 9.1 Demo目标

> 验证"在横版动作中使用格斗游戏式的择作为核心战斗系统"是否可行、是否好玩。

### 9.2 Demo包含

- 1个可操控角色（色块）
- 基础移动系统（跑、跳、冲刺）
- 输入仲裁系统（移动与战斗状态切换）
- 3层"择"的战斗系统（确反择、押注择、变招择）
- 2-3种小怪（覆盖基础出题类型）
- 1个Boss（综合出题，验证深度博弈）
- 1-2个机关（验证"择"延伸到世界交互）
- 1个简单场景（一个房间或线性短关卡）
- 基础打击反馈系统

### 9.3 Demo不包含

- 地图探索系统
- 角色成长/装备系统
- 完整美术资源
- 故事/叙事内容
- 音效/配乐（可用占位音效）
- 多个关卡/区域

### 9.4 验收标准

Demo做完后，回答以下问题：

1. **"择"成立吗？** 玩家在战斗中是否真的在做有意识的选择，还是无脑乱按也能赢？
2. **手感对吗？** 移动和战斗状态的切换是否自然？搓招的响应是否跟手？
3. **快感够吗？** 择对了的那一刻，有没有足够的满足感？
4. **不累吗？** 连续玩20分钟，是否觉得认知疲劳？
5. **有深度吗？** Boss战是否能让人反复挑战，每次都有新的理解？

> 如果以上5个问题中有3个以上得到肯定的回答，核心玩法验证通过，可以继续推进。

## 十、里程碑计划（3-6个月）

### Phase 0：基础设施搭建（第1-2周）

- Godot项目初始化、目录结构规范
- InputManager 原型：输入状态机 + 基础移动
- 色块角色 + 基础物理（移动、跳跃、重力）
- 版本控制搭建

### Phase 1：战斗核心原型（第3-6周）

- 基础招式系统（方向+攻击的快速出招）
- 连段系统（状态切换、连招路由）
- 输入仲裁调校（反复迭代手感）
- 打击反馈系统（顿帧、震屏、位移）
- **里程碑：角色在空房间里移动+出招，手感是否舒服**

### Phase 2：敌人原型（第7-10周）

- 敌人基础AI框架
- 实现2-3种小怪（直球型、多段型、变招型）
- 敌人出招预兆系统（视觉信号）
- "择"的判定逻辑（确反、押注、变招）
- **里程碑：跟小怪打起来，"择"的感觉是否成立**

### Phase 3：Boss与机关（第11-16周）

- Boss AI设计（多阶段、综合出题）
- 1-2个机关原型（喂招型 + 押注型）
- 资源系统（气槽积攒与消耗）
- 整体节奏测试（跑图 → 小怪 → 机关 → Boss）
- **里程碑：完整的一轮体验流程，核心循环是否成立**

### Phase 4：打磨与验证（第17-24周）

- 手感微调（大量反复测试）
- 数值平衡（伤害、资源、窗口时间）
- 找外部测试者试玩，收集反馈
- 根据反馈决定：继续 / 调整 / 放弃
- **里程碑：验收标准的5个问题是否大部分肯定**

## 十一、风险清单

| 风险 | 可能性 | 影响 | 对策 |
|------|--------|------|------|
| 输入仲裁手感调不出来 | 高 | 致命 | Phase 1全力投入，参考格斗游戏frame data设计，预留充足迭代时间 |
| "择"在小怪战中沦为无脑操作 | 中 | 严重 | 敌人AI需要有记忆性，根据玩家行为模式调整出题策略 |
| 敌人种类不够，"择"重复感强 | 中 | 严重 | 优先保证每种敌人出题方式独特，宁可少做也不做重复的 |
| 连段系统和变招系统过于复杂 | 中 | 中 | 先做确反择，确反择成立再扩展其他两层，逐步添加复杂度 |
| 搓招+跑图的节奏不兼容 | 中 | 严重 | 快速出招层完全不影响移动，只有连段层才锁定，保证跑图流畅 |
| 3-6个月内完不成Demo | 中 | 中 | 严格控制scope，砍掉一切非必要内容，机关可以先只做一个类型 |
