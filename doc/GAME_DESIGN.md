# Choice Project - 产品设计文档（Game Design Document）

> 版本：v0.3  |  日期：2026-08-03  |  状态：原型验证阶段

---

## 一、游戏概述

### 1.1 一句话描述

在类银河城的世界中，以格斗游戏式的"择"作为核心战斗体验——每一次交手都是一次有风险的判断，读对了就有高回报。

### 1.2 类型定位

- **基础类型：** 类银河城（Metroidvania）2D横版动作
- **差异化卖点：** 格斗游戏式的"择"战斗系统——不是按键连招，而是在连招中做有风险的即时选择
- **目标体验：** 紧张的对弈感 + 银河城的探索满足感

### 1.3 参考作品

| 作品 | 取什么 | 不取什么 |
|------|--------|---------|
| 九日 | 格挡贯穿始终的系统整合度、贴符资源管理 | 格挡本质是二元判断，深度有限 |
| 空洞骑士 | 世界氛围、碎片化叙事、探索驱动 | 跳跳乐与战斗偶有节奏割裂 |
| 恶魔城 | 银河城结构范式、成长回溯 | 战斗不是核心卖点 |
| 街霸 | "择"的灵魂——读对手、风险判断、确反快感 | 1v1结构不适合探索型游戏 |
| DNF | 搓招在横版中的爽快感 | 清版ACT结构，不是银河城 |

### 1.4 核心设计原则

1. **"择"是脊柱，不是附加功能。** 如果把这个系统拿掉，游戏就不成立了——这才是它应该达到的整合度。
2. **快感来自"我读对了"。** 不是"我手速快"，不是"我记住了"，而是"我在瞬间做出了最优判断"。
3. **有风险才有快感。** 没有押错的可能，就没有押对的兴奋。
4. **跑图是呼吸，战斗是心跳。** 两者交替出现，张弛有度，不能让玩家始终处于高压状态。
5. **执行服务于决策，不能喧宾夺主。** 搓招/连招的输入复杂度必须克制，它只是让玩家"表达选择"的工具。玩家有限的注意力一旦全被"能不能按出来"占据，就没有余力去做"该选哪个"的判断，项目的差异化就丢了。（详见 2.1.1 与风险章节）

## 二、核心玩法："择"

### 2.1 定义

"择"是战斗动作层面的即时判断——面对当前的局面，我该出哪套连招？

它不是广义的"做选择"（选A路线还是B路线），而是具体的、发生在每一帧里的战斗决策：敌人的攻击从上方来了，我用升龙迎击还是后撤躲避？Boss蓄力了，我该押一个大招还是保守打一套小连段？连到一半敌人变招了，我是继续打完还是变招抓新窗口？

### 2.1.1 关键区分：搓招（执行）≠ 择（决策）

这是本项目最容易走偏的地方，必须在整个开发周期内反复对照。

| 层面 | 搓招 / 连招（执行层） | 择（决策层） |
|------|---------------------|-------------|
| 本质 | 能否把一个输入序列物理性地按出来 | 在当前局面下该选哪个招 |
| 考验 | 手指、肌肉记忆、输入精度 | 判断、读局、风险评估 |
| 玩家念头 | "我能不能按出来" | "我该选哪个" |
| 代表作品 | DNF、传统格斗的指令表 | 街霸的对弈博弈、九日的格挡判断 |

**核心警示：** 格斗游戏两者兼有，但本项目的差异化卖点是"择"，不是"搓招"。搓招/连招系统只是让玩家把选择"表达"出来的工具——工具够用就行，不该成为主角。

**走偏的信号：** 当搓招表越设计越复杂（正摇、反摇、半圈、360度），玩家注意力会全部集中在"能不能按出来"，没有余力思考"该选哪个"。此时游戏就退化成 DNF 或传统格斗，丢掉了最初的差异化。

**判断标尺：** 每次设计一个招式或连招时，问自己——

> 我是在增加"执行难度"，还是在增加"选择空间"？

答案是前者 → 警惕，考虑简化输入。答案是后者 → 继续。

**真正的差异化住在哪：** 不在输入系统里，而在敌人设计和风险回报结构里。是"Boss露出破绽了，用A连招稳定打800，还是赌B连招打1500但可能被反打"这个纠结的瞬间。输入系统为这个瞬间服务。

### 2.2 "择"的三个层次

#### 层次一：确反择（读招回应）

**玩家心里的念头：** "它下一招是什么？我该用哪套连招接？"

敌人出招后露出破绽，破绽的类型决定了最优确反连招。选对了伤害翻倍，选错了只有普通伤害甚至被反打。

- 考验：反应速度 + 招式知识
- 节奏：快速判断，窗口短
- 适用场景：所有战斗（小怪到Boss）

#### 层次二：押注择（资源博弈）

**玩家心里的念头：** "这一波值不值得我把大招押上去？"

消耗积攒的资源释放大招，需要判断敌人接下来的行为窗口。押对了收益巨大，押错了空放浪费资源。

- 考验：风险评估 + 对敌人行为模式的预判
- 节奏：需要在短时间内做判断，但有思考空间
- 适用场景：精英怪、Boss战

#### 层次三：变招择（流动应变）

**玩家心里的念头：** "继续打完还是变招？变哪个？"

连段进行中，敌人突然变招（切换姿态、蓄力、暴露新破绽），玩家需要在连招途中判断是否中途cancel、切换到另一套连招。

- 考验：流动中的即时应变
- 节奏：发生在连招进行中，最紧张也最爽快
- 适用场景：精英怪、Boss战（高级博弈）

### 2.3 三层关系

三层不是互斥的，而是在一场战斗中可以同时出现、交替发生。

```
一场Boss战的节奏示意：

[开局] 确反择 → 读Boss第一招，选择回应
  ↓
[中期] 押注择 → 攒了气，要不要在这波交大招？
  ↓
[连段中] 变招择 → 打着打着Boss变招了，跟不跟？
  ↓
[收招] 确反择 → Boss露出大破绽，选择最优确反连招
```

### 2.4 "择"与普通动作游戏的区别

| 维度 | 普通横版动作 | 本项目的"择" |
|------|------------|-------------|
| 玩家思考 | "我要打它" | "我该怎么打它" |
| 连招意义 | 输出手段 | 决策工具 |
| 失误代价 | 少打一点伤害 | 被反打/浪费关键资源 |
| 成功快感 | "我连起来了" | "我读对了，选了最优解" |
| 学习曲线 | 记住连招按键 | 理解每个情境的最优选择 |

## 三、战斗系统

### 3.1 招式结构

角色的招式围绕"选择"而非"执行"设计。重点不在于能不能搓出来，而在于该不该选这一招。

**快速招式层（低门槛，跑图友好）：**
- 方向键 + 攻击键，一键释放
- 下劈、突刺、升龙、后撤斩等
- 不锁定移动，随时可以走位
- 用于日常跑图、小怪战

**连段层（中门槛，核心博弈）：**
- 连续输入触发多段连招
- 进入连段后方向键变为连招路由
- 可在连段中变招（cancel当前连段，切换新连招）
- 是"择"的主要发生层

**大招层（高门槛，高风险高回报）：**
- 消耗积攒资源（气槽）
- 释放前有蓄力动作，可被中断
- 命中收益巨大，空放血亏

### 3.2 控制映射

方向键的职责分离：移动归移动，搓招归搓招，跳跃独立出来。

| 按键 | 功能 | 说明 |
|------|------|------|
| ← → ↓ | 移动 + 搓招方向 | 银河城的标准移动方向 |
| ↑ | 仅用于攻击方向 / 搓招序列 | 不参与移动，只代表"向上出招"或搓招中的方向输入 |
| 空格 | 跳跃 | 独立于方向系统，高频操作用独立按键更直觉 |
| 攻击键 | 普攻 + 搓招确认 | 方向+攻击=快速招式，序列+攻击=连段/大招 |
| 闪避/冲刺键 | 位移 | 可打断搓招状态，是玩家的"逃生通道" |

**设计理由：**

格斗游戏中↑=跳跃，但银河城里跳跃是高频操作，用方向键跳不如空格直觉。将↑从移动中剥离，专门服务于攻击和搓招系统，避免了"我想上攻击但角色跳起来了"的冲突。搓招序列中出现的↑只代表攻击方向，不代表跳跃。

跳跃（空格）不参与"择"的系统，因此在调试UI的输入历史中默认不显示。如后续加入空中连招等机制再考虑纳入。

### 3.3 资源系统

**气槽：** 核心博弈资源。通过命中连招、成功确反来积攒，用于释放大招和变招。气槽管理本身也是一种"择"——现在用还是攒着等更好的窗口？

**血量：** 生存资源。被敌人击中会减少，归零则失败。

### 3.4 战斗节奏

```
跑图阶段（低压力）
  │
  ├── 遇到小怪 → 轻度择（确反为主），快速解决
  │
  ├── 遇到机关 → 中度择（单一层次），节奏变化
  │
  ├── 遇到精英 → 中度择（两到三个层次），需要认真对待
  │
  └── Boss战 → 重度择（三个层次全面展开），高潮体验
```

## 四、机关系统

机关是"择"从战斗延伸到世界交互的载体。它在跑图过程中作为节奏变化器存在，数量克制，体验精炼。

### 4.1 方案A：喂招型

**体验描述：** 机关向你"出招"，你需要用正确的连招"接招"。

机关激活后释放信号（能量束、冲撞、弱点暴露），玩家需要在瞬间判断该用哪套连招回应。判对了解锁，判错了受罚但可以重试。

**核心感受：** "我读懂了机关的招式。"

### 4.2 方案B：押注型

**体验描述：** 机关要求你押上资源，你要判断值不值得。

蓄力释放大招来激活机关，消耗积攒的气。但机关有真有假，需要判断这个机关是否值得投入。

**核心感受：** "我赌对了，这一把值。"

### 4.3 方案C：变招型

**体验描述：** 机关跟你"过招"，连到一半它会变，你得跟着变。

交手过程中机关会切换状态，暴露新窗口，玩家需要在连招途中判断是否变招。

**核心感受：** "我的节奏没断，跟上去了。"

### 4.4 机关设计原则

- 三种类型交替出现，避免重复感
- 前期单一类型，后期可混合
- 每次视觉包装不同，即使底层逻辑相同
- 总量克制：全地图预计10个左右
- 是节奏点缀，不是解谜主体

## 五、敌人设计

### 5.1 核心要求

敌人必须能"出题"。如果面对一个敌人时玩家不需要思考就能赢，这个敌人的"择"就失败了。

### 5.2 敌人分类（Demo阶段）

**直球型（确反择训练）：**
- 攻击前摇明显，破绽固定
- 教会玩家"读出攻击 → 选择确反连招"
- 1-2种变体，通过攻击方式不同提供差异

**多段型（押注择训练）：**
- 连续攻击，最后一段才有大破绽
- 玩家要在"忍到最后吃大确反"和"中途打断求稳"之间选择
- 1种

**变招型（变招择训练）：**
- 攻击过程中会切换模式
- 玩家的连段打到一半需要应变
- 1种

**Boss（综合考验）：**
- 多阶段，综合运用所有出题方式
- 不同阶段节奏不同，考验不同层次的择
- 1个

### 5.3 敌人行为准则

- 每个敌人出招前必须有可读取的视觉预兆
- 预兆不能太明显（否则无脑），也不能太隐晦（否则看不懂）
- 行为有一定随机性，保持"择"的不确定感
- 出题节奏要有变化，不能每次都一样
- 敌人要"教"玩家——第一次遇到时给出清晰信号，后续再增加复杂度

## 六、玩家体验目标

### 6.1 理想中的玩家感受

**战斗中：** "这个敌人接下来要干嘛？我该用哪套连招？赌一把还是求稳？——漂亮，我读对了！"

**跑图中：** "这个机关有意思，搓一个看看……嗯，来了，择对了，继续走。"

**Boss战后：** "这场打得太紧张了，中间那波变招我差点没接住，但押对大招那一下太爽了。"

**失败后：** "我知道刚才哪里选错了，下一次我换个策略。"

### 6.2 不希望出现的感受

- **疲惫感：** "每次打架都要想这么多，好累。" → 对策：小怪战轻量化，Boss战才有深度博弈
- **困惑感：** "我完全不知道该选哪个。" → 对策：视觉预兆清晰，敌人"教"玩家
- **无力感：** "我选什么都没用。" → 对策：确保每个情境都有合理的最优解，不存在无解局面
- **无聊感：** "又是这种敌人，打法一模一样。" → 对策：敌人种类虽少但出题方式各异

## 七、美术方向（概念）

> 注：Demo阶段使用色块占位，此处记录后期方向供参考。

### 7.1 待定方向

世界观和美术风格待核心玩法验证后再确定。候选方向：
- 暗黑奇幻（哥特、古堡、宗教）
- 东方幻想（神话体系、原创生物）
- 科幻/赛博（科技与传统文化融合）
- 完全原创世界

### 7.2 美术原则（无论哪种风格）

- 敌人出招预兆必须在视觉上清晰可读
- 打击反馈要"重"，让玩家感受到选择正确的分量
- 场景服务于探索节奏，不能喧宾夺主

## 八、Demo验收标准

Demo完成后，用以下问题检验核心玩法是否成立：

| # | 问题 | 通过标准 |
|---|------|---------|
| 1 | "择"成立吗？ | 玩家在战斗中有意识地做选择，而非无脑乱按 |
| 2 | 手感对吗？ | 移动和战斗状态切换自然，搓招响应跟手 |
| 3 | 快感够吗？ | 择对了的瞬间有足够的满足感和正反馈 |
| 4 | 不累吗？ | 连续玩20分钟不觉得认知疲劳 |
| 5 | 有深度吗？ | Boss战让人想反复挑战，每次有新理解 |

> 5项中至少3项获得肯定回答，核心玩法验证通过。

## 九、核心设计风险与止损线

### 9.1 最大风险："择"可能根本不成立

本项目的核心假设是：玩家会在战斗中主动思考、做选择。

但现实可能是：**玩家无脑乱按也能赢，"择"从未真正发生。**

如果玩家发现"一直按招式3就能打赢Boss"，那整个设计前提就崩塌了。"择"不是设计出来的，是被迫出现的——因为没有万能选项，玩家才不得不思考。

**这意味着：90%的设计工作量，可能都在"消灭最优解"上。**

### 9.2 设计漂移风险：从"择"滑向"搓招"

这是与9.1并列的第二大风险，且在开发中更隐蔽、更容易不知不觉发生。

**风险描述：** 开发重心从"决策层"漂移到"执行层"。表现为搓招表越设计越复杂、输入系统越做越精细，但"玩家该选哪个招"的决策空间却没有同步增加。最终做出一个考验手速和输入精度的格斗/清版游戏，而非最初设想的"有风险的连招选择"。

**为什么隐蔽：** Phase 0/1 本来就是搭输入和战斗地基，执行层主导是正常的。但如果没有警觉，地基的复杂度会惯性膨胀，挤占决策层的设计空间。

**自查信号（出现任意一条就要警惕）：**
- 设计新招式时，花在想"输入指令怎么搓"上的时间，超过想"它提供什么选择"的时间
- 搓招表里出现正摇、反摇、半圈、360度等高复杂度指令
- 测试时自己脑子里想的是"这招没按出来"，而不是"这招该不该用"
- 连招数量在涨，但敌人出题方式和风险回报结构没有同步丰富

**对策：**
- 输入复杂度克制——能用简单输入表达的招式，不用复杂输入
- 设计精力向敌人出题、风险回报结构倾斜，那才是差异化所在
- 每次迭代对照 2.1.1 的判断标尺："我在增加执行难度，还是选择空间？"

### 9.3 消灭最优解的方向

| 方法 | 说明 |
|------|------|
| AI反制重复打法 | 敌人识别玩家重复使用同一招式，开始出克制该招式的攻击 |
| 招式间猜拳关系 | 不是固定映射，而是"招式3打A很强，但A有时变A'，招式3打A'会被反杀" |
| 资源/状态限制 | 强力招式消耗气槽或有长后摇，不能无限使用 |
| 可读的随机性 | Boss行为有概率分布，玩家无法背板，但有视觉线索可预判 |

### 9.4 止损线：Phase 2 结束时

**如果 Phase 2 结束时以下问题的答案是否定的，建议停手：**

| # | 问题 | 否定意味着 |
|---|------|-----------|
| 1 | 面对敌人时，我会犹豫用哪招吗？ | "择"不存在 → **核心失败** |
| 2 | 选对了和乱按，体感有明显差异吗？ | 反馈系统失败 → 可补救 |
| 3 | 打同一个敌人第二遍，我的策略会变吗？ | 最优解没消灭 → Boss设计问题 |
| 4 | 我愿意反复打这个敌人吗？ | 没有深度 → **核心失败** |

**判断标准：**
- 第1、4题为否 → 核心设计不成立，建议停手或大幅转向
- 第2题为否 → 可以调，属于技术问题
- 第3题为否 → 可以调，但需要大量Boss设计迭代
