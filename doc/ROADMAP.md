## 一、开发方式变更（2026-11-04，破坏性）

### 1.1 为什么改

截至 2026-11-04，项目状态是：**工程与文档完成度高，玩法验证几乎没有开始。**

- 3 个月（含中断）产出 1733 行 C#、18 个场景、1541 行文档；
- 核心机制（识破/霸体、做局骗/踉跄、承诺招/抓挥空）已跑通并有实测；
- 但 2026-11-04 的基线实测确认：**交替两招即可 3 秒零伤击杀敌人**，项目的头号失败模式
  "无脑乱按也能赢" 在当前版本成立；
- 结论：**瓶颈不是实现能力，是设计验证的次数。** 手搓代码把时间花在了非瓶颈上。

因此在 2026-11-04 切换开发方式。**否决的是"方式"，不是"成果"**——见 1.3 保留清单。

### 1.2 被否决的（不再作为工作方式）

| # | 旧方式 | 否决理由 |
|---|--------|---------|
| 1 | 手搓每一行代码是主要工作方式 | 时间花在非瓶颈；且手搓 Godot C# 学到的是 C#，不是 Godot |
| 2 | 用"加了什么系统/内容"衡量进度 | 免费解未消灭时，加得越多离目标越远 |
| 3 | 立项文档 [`PROJECT_DESIGN.md`](archive/PROJECT_DESIGN_v0.1.md) 的"三层择"作为核心模型 | 已被 2026-09-29 的「非对称赌注」模型取代，且从未正式收编；立项文档已归档 |
| 4 | 任务表式排期（"第 N 周做 X"） | 无退出条件、与验证脱钩，实际已失效 |
| 5 | 产品级决策写在开发日志里 | 未来的你/合作者会读到错误模型；产品决策归 `GAME_DESIGN.md` |
| 6 | "边做边补文档" | 决策与实现脱节，2026-09/10 的漂移即由此产生 |

### 1.3 保留的（这些资产不动）

- **架构骨架**：判定件哑组件（Hitbox/Hurtbox）、输入采集与仲裁分离、MoveData 帧数据、敌人相位机；
- **引擎经验**：`flushing_queries` / `SetDeferred`、顿帧单计数器、输入消费契约（`DEV_GUIDE` §4.4/§4.5/§4.7）；
- **颜色语言**：6 色 telegraph + 识破前后摇变体；
- **AI 行骗红线**：金 tell 永不撒谎、不掷骰子、可复盘；
- **文档习惯**：决策记录 / 红线 / 调参顺序 / 阶段回溯；
- **已被实证的手感**：顿帧、震屏、闪避打断、抓挥空反斩、做局骗踉跄。

### 1.4 新分工

| 角色 | 谁 | 具体 |
|------|----|------|
| 方向 | 你 | 拍板设计分叉、定范围、说"不成立" |
| 验收 | 你 | 每批打三分钟 + 一句结论 |
| 实现 | AI | 代码 + 场景/资源（`.tscn`/`.tres` 文本即编辑器数据模型） |
| 自测 | AI | headless 断言 + 运行截图 + 回归 |
| 文档 | AI 起草，你确认 | 决策、数值、教训 |

### 1.5 证据标准（一批算不算完成）

1. `dotnet build` 0 error；
2. 机制断言全绿（`tests/`，headless）；
3. 运行截图 + 一句"这次该看什么"；
4. 你的三分钟结论（成立 / 不成立 / 哪里不对）。

> 只有 1–3 没有 4 = **未完成**；只有 4 没有 3 = **不可复核**。

### 1.6 协作协议

- **一批 = 一个 commit**，diff ≤ ~300 行，标题写清"该验什么"；
- 每批交付四样：可跑 build / 一句话验法 / 断言结果 / 已知未做；
- **设计分叉只在批次边界问**，实现中途不打扰；
- **不扩范围**：想到的东西进 `BACKLOG.md`，不顺手做；
- 手感改坏了**回滚一个 commit**，不做局部缝补。

|--------|------|---------------|------|
| **M0 基座收口** | 让后续每一批都可复核 | 断言能跑；build/沙盒分离；文档体系落地 | 🔨 进行中 |

### 各里程碑要点

**M0 · 基座收口**——不是功能，是"可复核性"。没有断言和 build/沙盒分离，后面每批都只能靠你反复试玩，那是不可持续的。产出：`tests/` 断言、沙盒场景、截图自动化、`BACKLOG`。

**M1 · 回合**——当前真正的瓶颈。敌人拿不到回合，"择"就不可能发生。原则见 `GAME_DESIGN` §2.5。**B 批已锁定短促交锋。**

**M2 · 三个问题**——从"一个免费解"变成"一局要判断两三次"。敌人第二招、玩家重招的用途、节奏起伏。

**M3 · 外部验证**——项目至今**从未被外部验证过**。这一关只问两件事：会不会自发换招/收手；失败后能不能说出"我该换一招"。不过 = 停止加内容。

**M4 · 第二敌人**——先做 `MoveRunner`/`Health` 接缝重构，再写敌人；**只写"出题逻辑 + tell"**。判据是"1–2 天能加完"，证明机制可复制，而不是每个敌人都是一次性工程。

**M5 · Boss**——三阶段、综合三类题、阶段切换带新 tell。判定"深度"的唯一标准是：第二遍打法会变。

**M6 · 容器**——方向未定（见 §六）。Boss Rush 成本低、验证快；银河城是完整愿景但成本翻倍。

**M7 · 表现**——色块/剪影、代码驱动动画、音效、镜头。目标不是好看，是**关掉文字也读得懂**。

**M8 · 收尾**——平衡、教学、设置、存档、构建发布。

## 五、接下来三批

| 批次 | 内容 | 验收（L1 + L2） |
|------|------|-----------------|
| **A** | `tests/` 断言 + 沙盒/`build` 分离 + 截图脚本 | 断言全绿；你打三分钟确认无退化 |
| **B** | 压力读 + 去双叠 + 战斗时长（~250 HP） | 断言："交替连打 30 秒必须被惩罚"；你："我被逼着停手了" |
| **C** | 敌人第二招 + 一局三题节奏 | 断言：一局 ≥3 次判断时刻；你："每一下都在选" |

### B 批已锁定：短促交锋（2026-11-04 拍板）

- **压力读（解围）**：连续被命中 N 次（**不看招名**）→ 打断硬直、起一个带霸体的快反。这是"交替两招"免费解的正解，因为压力是绕不过去的维度。
- **tell 规则**：沿用金色，但用**闪烁**区分"解围霸体（躲就对了）"与"识破某招（换招能打穿）"——避免文档警告过的"双金陷阱"。
- **去双叠**：霸体反击命中后立即关闭敌人攻击判定 → 一次错误只吃一口，不再 −18 又 −12。
- **时长**：敌人 HP 50 → 250（一局 20–25 秒），让一局装得下 2–3 个问题。
- **起始数值**（全部可调，先按分诊顺序微调，不一次性乱调）：N=3 次 / 窗口 90 帧 / 解围 startup 6–8 帧。

## 七、风险与止损

| 风险 | 触发信号 | 动作 |
|------|---------|------|
| "择"根本不成立 | M3 时 5 人里 <3 人自发换招 | **停止加内容**，二选一：降维成"确反+押注"纯格斗，或换容器成 roguelite |
| 压力读无效 | M1 两批内免费解仍在 | 升级到设计讨论，不硬推；考虑击退+敌人移动（把"距离"变成真轴） |
| 敌人变成"猜拳" | 玩家觉得解围是随机 | 提高解围的可读性（tell 提前量、次数提示），而不是降低强度 |
| AI 实现改坏手感 | L2 连续两次"不成立" | 回滚一个 commit，重新拆批 |
| 范围膨胀 | BACKLOG 里的东西被顺手做了 | 立即拆出来，回到当前批次 |
