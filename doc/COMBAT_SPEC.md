### 1.2 状态机总览

```
                    ┌──────────── 攻击键 ────────────┐
   MovementHandler ─┼──────────── 闪避键 ───────────→ DodgeHandler
   （地面/空中共用）  └──────────── 被命中 ───────────→ HitstunHandler
        ↑                  ↑                              │
        └──────────────────┴──────────────────────────────┘
                        （招式/闪避/硬直结束）
```

| 状态 | 承载 | 进入条件 | 退出条件 | 备注 |
|------|------|---------|---------|------|
| **Movement** | `MovementHandler` | 常态 | 攻击/闪避/受击 | 地面与空中没有分开建模（⏳ M2 若做平台跳跃再拆） |
| **Combat** | `CombatHandler` | 攻击键按下边缘 | 招式播放完 / 被闪避打断 / 被命中打断 | 播放期锁走位由 `MoveData.lockMovement` 决定 |
| **Dodge** | `DodgeHandler` | 闪避键按下边缘 且 冷却为 0 且 当前招允许取消 | 12 帧后 | 全程无敌 |
| **Hitstun** | `HitstunHandler` | 被命中 | 18 帧后 | 不可闪避取消（**只能挨着**） |
| **Dead** | 尚未建模 | HP ≤ 0 | 2 秒后重载场景 | ⏳ M2 需要正式的死亡/重来 |

**连段规则：** 一招播放结束时，若输入日志里有新的攻击按下边缘，且未达 `chainCap`，则无缝接下一招；否则立刻还移动。
`chainCap = 3`，**M1 不改**。

> **起草时的一次自我否决：** 原本打算把 `chainCap` 降到 2，用系统强制"打两下"。否决理由：
> 第 3 下会被 `chainCap` 挡掉，而缓冲里的输入也随之作废——玩家会觉得"我按了它没出招"，
> 本质是用规则代替选择。**让"要不要打第三下"成为玩家的选择（由压力条施压），而不是系统的禁令。**

### 1.4 逐个动作的定义

**jab（安全招）**
- 作用：试探、抢节奏、拿低风险收益。
- 为什么气耗 0：**安全选项不该有资源门槛**，否则玩家会"因为没气而不敢试探"，节奏断掉。
- 为什么可闪避取消：它是"后悔药"，压制到一半发现不对可以跑。
- 代价：伤害低、被识破时同样吃霸体反打。

**heavy（承诺招）**
- 作用：高风险高回报，是"押注"的实体。
- 为什么不可取消：**没有承诺就没有赌注**。这是 2026-10-09 取向 R 的核心。
- 挥空 → `WhiffPunishable` → 敌人可起长距离反斩（已有机制）。
- 气耗 25：一管气只能连打 4 发，之后要等回气——这让"这一发要不要交"变成真问题。

**闪避（防御臂）**
- 全程无敌 12 帧 + 60 帧冷却。
- 定位是"择错之后的纠错通道"，不是默认站姿（GAME_DESIGN §2.1.3）。
- ⏳ M2 评估：冷却是否要拉到 90 帧，让"闪避还在 CD、敌人下一招已到"真的出现。

**跳跃**
- 只服务于移动与跑图，不参与"择"（GAME_DESIGN §3.2 决策记录）。
- 空中没有独立状态，空中控制 = 全速（⏳ M2 若做平台内容再调成 0.7 倍）。

### 1.5 明确不做的动作（及理由）

| 动作 | 决定 | 理由 |
|------|------|------|
| **格挡** | ❌ 不做 | ①闪避已经是防御臂，两个防御键会让"站着挡"变成万能解；②做格挡就必须配套"破防/削韧/崩防"，是一整套系统，成本远超收益；③它会破坏"读招 → 躲或确反"的二选一结构。**M5 做 Boss 时若发现防御手段不够再重新评估。** |
| **↑ 攻击（上挑/升龙）** | ❌ 暂不做 | 它的价值是"挑空 → 空中追击"的押注择，而**空中连段已随短促交锋移出范围**。没有空中追击，上挑就只是一个向上的普通攻击。等有空中敌人或平台内容再议。 |
| **↓ 攻击（下劈）** | ❌ 暂不做 | 同上，它的对手戏是"蹲防/低姿态敌人"，当前敌人没有这些状态。 |
| **空中攻击** | ❌ 暂不做 | 需要空中状态、空中受击、落地硬直一整套；且短促交锋的战场目前是地面。 |
| **大招** | ⏳ M5 之后 | 需要气槽经济先立起来（M1 刚把气变成约束），且需要 Boss 级别的时间尺度才承载得住。 |
| **处决 / 投技 / 反击技** | ❌ 不做 | 会稀释"读招"这条主线。 |

> **这一节的意义：** 角色的"完整"不等于"动作多"。**一个只有 4 个动作但每个都有代价的角色，比 12 个动作但 10 个是摆设的角色更完整。** 上面每个 ❌ 都写死了理由，将来想加必须先推翻理由。

## 二、操作规格

### 2.1 键位（键鼠，暂不做手柄）

| 功能 | 键 | 备注 |
|------|----|------|
| 移动 | ← → | 只有左右；↑↓ 不参与移动（决策记录 2026-08-14） |
| 攻击 | Z / X / A / S | 四键**当前等价**，选招看方向 |
| 跳跃 | 空格 | 独立键 |
| 闪避 | Shift | |
| 格挡 | C | 已绑定，**未实现且暂不做** |

> 🔨 **M1 决定：四攻击键收敛为两个**（Z=攻击，X=重攻击）还是**保持四键等价**？
> 倾向收敛：四键等价会让"按哪个键"变成噪声，而本作的原则是"执行服务于决策"。
> **但这一条我不擅自改，等你说。** 若收敛，M1 不动，M2 再动输入表。

### 2.2 方向语义

- **绝对方向**：↑↓←→ 直接选招，不做"前/后"相对朝向的映射（无对手时的历史决策，现在敌人只在右/左侧，仍成立）。
- **出招朝向** = 出招瞬间按下的水平方向；无水平方向时沿用 `facing`（2026-11-04 修复）。
- **方向只决定"哪一招"，不决定"打多远"**——判定框始终朝向出招方向。

### 2.3 输入优先级（不可回退）

```
受击请求  >  闪避  >  顿帧闸门  >  普通 Tick
```

- 受击：请求化，下一帧立刻打断当前动作。
- 闪避：在顿帧闸门**之前**判定，所以顿帧期间也能闪。
- **例外**：闪避无敌期内被命中 → 命中无效（不触发受击）。

### 2.4 缓冲与容忍

| 机制 | 当前 | M1 目标 | 说明 |
|------|------|---------|------|
| 攻击缓冲 | ✅ 回扫 60 条输入日志 | 保持 | 顿帧/硬直期间按下的攻击不丢 |
| 跳跃缓冲 | ❌ 无 | ⏳ M2 | 落地前 6 帧按跳算数（需要平台内容才能验） |
| 土狼时间 | ❌ 无 | ⏳ M2 | 离开平台后 6 帧内仍可起跳 |
| 闪避缓冲 | ❌ 无 | 🔨 M1 评估 | 4 帧；当前只认当帧边缘 |
| 连段输入 | ✅ | 保持 | 招式结束瞬间取缓冲里的新边缘 |

### 2.5 已知输入缺陷

| 缺陷 | 影响 | 何时修 |
|------|------|--------|
| 硬直/顿帧期间的单帧攻击边缘被吞 | 玩家觉得"我按了没出招" | ⏳ M2（被读→硬直→回归节奏会最痛） |
| 闪避方向写死为 facing（`_dodgeDirection` 未用） | 不能"后撤步" | ⏳ M2 |
| 无手柄支持 | — | ❌ 不做（Demo 阶段） |

### 3.5 手感的主观验收（不是数字，是体感）

1. 从按键到画面有反馈 **≤ 4 帧**（肉眼不觉得延迟）；
2. 出招后**立刻能感觉到"我进入了硬直"**（不能出现"按了没反应"的空窗）；
3. 被击中时**知道自己为什么被打中**（颜色/位置能复盘）；
4. 闪避的"无敌"要能被**看见**（蓝 + 穿过攻击）。

## 四、敌人规格

### 4.1 出题结构（每个敌人都一样）

```
Idle（白） → Startup（黄，出题） → Active（红） → Recovery（绿，破绽） → Idle
                    ↑                                          │
                    └────────── 被打断 / 识破 / 解围 ───────────┘
```

- **Startup 必须可读**：颜色 + 朝向在起手瞬间锁定，玩家据此决定躲还是确反。
- **Recovery 是给玩家的奖励窗口**：绿 = 安全确反。
- **被打断**：命中 → Hitstun（紫）→ Idle。*（当前"全可打断"，是教学敌人的设定，不是所有敌人的规则。）*

### 4.2 两种"读"（M1 新增第二种）

| 读法 | 触发条件 | 反应 | 玩家的应对 |
|------|---------|------|-----------|
| **名字读**（已有） | 同一招连续命中 3 次 | 金常亮 + 霸体反打 | 换招打穿 |
| **压力读**（🔨 M1） | 压力条满 3 格时被命中 | 金闪烁 + 解围反击 | 收手 / 用 jab 骗后闪 |

**为什么必须有第二种：** 名字读只看 `_lastMoveId`，玩家 A/B 交替就能永久绕过——这是 2026-11-04 实测确认的免费解。**压力是绕不过去的维度。**

### 4.3 压力 / 解围（M1 核心）

| 项 | 值 | 说明 |
|----|----|------|
| 压力条上限 | 3 格 | 敌人头顶显示 |
| 每被命中 | +1 格 | 不看招名 |
| 衰减 | 1 格 / 秒 | 让"收手"有收益 |
| 触发 | **第 3 次命中把条打满的那一刻** | 第 1、2 下安全；第 3 下危险 |
| 解围前摇 | 10 帧 | 金闪烁，可反应 |
| 解围伤害 | 10 | |
| 解围打空 | 进入 35 帧 Recovery | 玩家的奖励窗口（比普通后摇长） |

**三个选项（这就是 M1 要交付的"择"）：**

| 你的选择 | 结果 |
|---------|------|
| 条满时收手，等它掉格 | 安全，但少打一套 |
| 第三下用 **jab**，见金闪就闪 | 骗出解围 → 它扑空 → 你确反（正收益） |
| 第三下用 **heavy** | 躲不掉 → 吃一下（贪的代价） |

### 4.4 tell 语言

见 §1.6 色表。新增一条不变式：**同一颜色必须对应同一应对**。
- 金常亮 = 换招能打穿
- 金闪烁 = 换招也没用，只能躲

| 项 | 当前 | M1 目标 |
|----|------|---------|

| 攻击帧 | 30/6/40 | 30/6/40（不变） |

## 五、一局（遭遇）的结构

| 项 | 目标 |
|----|------|
| 形式 | 1 房间，玩家 vs 1 敌人，平地 |
| 时长 | **20–25 秒** |
| 判断次数 | 3–5 次（每次约 4–6 秒） |
| 玩家容错 | 8–10 下（HP 100 / 敌人 10 伤） |
| 击杀所需 | 约 20 次 jab 或 8 次 heavy 或混合 |
| 失败 | 玩家死亡 → 2 秒后重载（M1 先这样，M2 正式做死亡流程） |

**一局的节奏（目标体感）：**

```
0s   靠近，读起手 → 躲
3s   确反，打 2 下
5s   条满 2/3 → 判断：收手 or 贪第三下
8s   敌人再出题 → 躲/换招
12s  骗一次解围 → 它扑空 → 罚一套
18s  血量见底 → 收尾
22s  结束
```

## 九、调参顺序（只允许一次动一个）

1. **先看时长**：一局不在 20–25 秒 → 只调敌人 HP；
2. **再看判断次数**：一局少于 3 次判断 → 只调解围前摇/压力衰减；
3. **再看压力**：玩家总是被解围打死 → 先降解围伤害，再放宽前摇，**最后才动格数**；
4. **最后看数值**：伤害/气耗只在手感定型后调。
