## 〇、铁律（每条机制上线前必须逐条过）

> 这几条不是"建议"，是**验收项**。过不了就是 bug，不允许"先这样，以后再说"。

### 铁律 1 · 回合归属

**每次交互结算后，必须能明确回答：这一回合归谁。**

自查三步：

1. 把一次交互拆成 **谁发起 → 谁被惩罚 → 谁拿到下一个行动权**；
2. **任何让"被惩罚的一方"同时获得收益的分支，都是 bug**；
3. 奖励（踉跄、确反窗、额外伤害、资源）只能发给**这一回合的赢家**。

落地检查表（新增机制时逐条问）：

- [ ] 结算完成后，输家还能不能立刻反击？
- [ ] 这个奖励窗口是因为"赢家赢了"，还是因为"输家自己失误了"？
- [ ] 有没有任何一条路径，让惩罚和奖励同时落到同一个人身上？
- [ ] 同一个动作会不会被结算两次（双叠）？

**已记录在案的事故（两次，都发生在同一天）：**

| 时间 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 2026-11-04 | 霸体反击 -18 之后，敌人普攻仍命中再 -12（双叠） | 结算后没有结束敌人的这一刀 | `OnArmorPunishResolved()` 关判定框 |
| 2026-11-04 | 被架住 -18 之后敌人扑空踉跄，玩家反而白拿 ×3 | `Stagger` 只看"预判非空且未命中"，不看"这一回合谁赢" | 同上：架住即回合结算 |

> **推论（给写代码的人）：** 每个"给奖励"的分支，都必须知道**上一笔结算的输家是谁**。
> 如果那个分支拿不到这个信息，就是设计缺口——先补信息，再补逻辑。

### 1.2 状态机总览

**连段规则：** 一招播放结束时，若输入日志里有新的攻击按下边缘，且未达 `chainCap`，则无缝接下一招；否则立刻还移动。
`chainCap = 3`，**M1 不改**。

> **起草时的一次自我否决：** 原本打算把 `chainCap` 降到 2，用系统强制"打两下"。否决理由：
> 第 3 下会被 `chainCap` 挡掉，而缓冲里的输入也随之作废——玩家会觉得"我按了它没出招"，
> 本质是用规则代替选择。**让"要不要打第三下"成为玩家的选择（由压力条施压），而不是系统的禁令。**

### 1.4 逐个动作的定义

**jab（安全招）**
- 作用：试探、抢节奏、拿低风险收益。
- 为什么气耗 0：**安全选项不该有资源门槛**，否则玩家会"因为没气而不敢试探"，节奏断掉。
- 为什么可闪避取消：它是"后悔药"，压制到一半发现不对可以跑。
- 代价：伤害低、被识破时同样吃霸体反打。

**出招位移（数据驱动，2026-11-04）**
- `MoveData` 三段各有一个位移量（相对朝向，像素）：`startupShift / activeShift / recoveryShift`，按段帧数均摊成速度。
- **判定框是身体的子节点，会跟着一起动**——判定期前冲等于动态延长攻击距离，后摇回收等于缩短，这是有意的。
- 轻拳三段全 0（不承诺、不位移）；重拳 起手 -4 / 判定 +12 / 后摇 -8，净位移 0。
- 未来的突进 / 升龙 / 后撤斩直接复用这组字段，不用改代码。竖直方向等有需求再加 `Vector2` 版。

**heavy（承诺招）**
- 作用：高风险高回报，是"押注"的实体。
- 为什么不可取消：**没有承诺就没有赌注**。这是 2026-10-09 取向 R 的核心。
- 挥空 → `WhiffPunishable` → 敌人可起长距离反斩（已有机制）。
- 气耗 25：一管气只能连打 4 发，之后要等回气——这让"这一发要不要交"变成真问题。

**闪避（防御臂）**
- 全程无敌 12 帧 + 60 帧冷却。
- **可穿过敌人身体**：敌人身体在独立物理层 `enemy_body`（层 6），闪避期间临时把自己的 `CollisionMask` 去掉该层，
  结束后还原——地面/墙壁仍在世界层，照常碰撞。**只改 mask，不改 shape**，不触发物理 flush 限制。
- 定位是"择错之后的纠错通道"，不是默认站姿（GAME_DESIGN §2.1.3）。
- ⏳ M2 评估：冷却是否要拉到 90 帧，让"闪避还在 CD、敌人下一招已到"真的出现。

**跳跃**
- 只服务于移动与跑图，不参与"择"（GAME_DESIGN §3.2 决策记录）。
- 空中没有独立状态，空中控制 = 全速（⏳ M2 若做平台内容再调成 0.7 倍）。

**格挡（⏳ M2，与敌人的"破防招"捆绑上线）**
- 输入：按住 `C`。
- 效果：减伤 70%，格挡硬直 8 帧，格挡期间**不能攻击**（逼出"挡完要重新起势"）。
- 成本：每次成功格挡消耗 **15 气**；气不足时 `C` 无效（按键无反应 + 视觉提示）。
- 破防：敌人的**破防招**对格挡中的玩家造成**全额伤害 + 20 帧硬直**，tell 与普通攻击明确区分。
- **为什么用气、不是新加一条"韧性条"：** 让气同时是**进攻资源**（heavy）和**防御资源**（格挡）——
  "这一口气是拿去打，还是留着挡"本身就是一个押注，不需要新建系统。
- **为什么不是 100% 减伤：** 无敌的防御会让"躲"失去意义，龟缩会变成第二个万能解。
- **为什么不在 M1：** M1 的题目是"敌人有没有回合"。格挡必须有一个**针对它的招**才有对手戏，
  而那正好是 M2 的"敌人第二招"。**先有破防招，再有格挡**，顺序反了就是空壳。

### 1.5 明确不做的动作（及理由）

| 动作 | 决定 | 理由 |
|------|------|------|
| **格挡** | ⏳ **M2 做**（和"敌人破防招"捆绑） | 你的原始判断是对的：**格挡 + 针对格挡的招 = 一个真正的择**。但单独做格挡会变成没有对手戏的空壳，所以不在 M1 做，而是和 M2 的第二招一起上。规格见 §1.4。 |
| **↑ 攻击（上挑/升龙）** | ❌ 暂不做 | 它的价值是"挑空 → 空中追击"的押注择，而**空中连段已随短促交锋移出范围**。没有空中追击，上挑就只是一个向上的普通攻击。等有空中敌人或平台内容再议。 |
| **↓ 攻击（下劈）** | ❌ 暂不做 | 同上，它的对手戏是"蹲防/低姿态敌人"，当前敌人没有这些状态。 |
| **空中攻击** | ❌ 暂不做 | 需要空中状态、空中受击、落地硬直一整套；且短促交锋的战场目前是地面。 |
| **大招** | ⏳ M5 之后 | 需要气槽经济先立起来（M1 刚把气变成约束），且需要 Boss 级别的时间尺度才承载得住。 |
| **处决 / 投技 / 反击技** | ❌ 不做 | 会稀释"读招"这条主线。 |

> **这一节的意义：** 角色的"完整"不等于"动作多"。**一个只有 4 个动作但每个都有代价的角色，比 12 个动作但 10 个是摆设的角色更完整。** 上面每个 ❌ 都写死了理由，将来想加必须先推翻理由。

### 1.6 视觉状态（色块语言）

| 状态 | 颜色 | 说明 |
|------|------|------|
| Idle / Movement | 白 | |
| 招式 Startup | 黄 `(1,0.85,0)` | 起手预警 |
| 招式 Active | 红 `(1,0.1,0.1)` | 判定生效 |
| 招式 Recovery | 绿 `(0.1,1,0.4)` | 破绽 |
| Hitstun | 紫 `(0.7,0.2,1)` | 受击 |
| Dodge | 蓝 `(0.2,0.5,1)` | 无敌 |
| 敌人·**识破某招** | **白色细描边**（常亮，贯穿 Startup/Active/Recovery） | 那一招打了没用；**换招可打穿 / 收手** |
| 敌人·**解围** | **金色粗描边 + 闪烁** | 什么都打不进去；**只能躲 / 停手** |
| 敌人·踉跄 | 青白闪烁 | 扑空大破绽，×3 |

> **2026-11-04 改为双通道（方案 B）：**
> **色相只表示相位（何时），金色外描边只表示免疫（能不能打）。**
> 原来的"毒黄绿（后摇被污染）"取消——它和绿只差一点色相，靠色相区分两个维度必然失败。
> 现在：看到黄/红/绿 → 判断躲不躲；看到**白边** → 别用那一招；看到**金边在闪** → 它要解围，只能躲。
> **两种免疫必须视觉可分**——它们正确的应对相反（换招 vs 只能躲），共用一个颜色就是这个项目已经踩过两次的坑。

**挥击表现（2026-11-04，玩家侧）**

| 通道 | 轻拳 | 重拳 |
|------|------|------|
| 判定框形状 | 细长 `90×14` | 粗壮 `120×34` |
| 挥击块颜色 | 冷蓝 `(0.7,0.9,1)` | 橙红 `(1,0.55,0.15)` |
| 命中火花 | 10 粒、冷色 | 28 粒、暖色 |
| 身体色 | 仍按相位（黄/红/绿） | 同 |

> **原则：形状 + 招式色 + 火花三个通道一起变，不靠单一维度。**
> 起手期用半透明预演框（招式色），判定期换成**实心**挥击块，后摇期隐藏。
> 颜色字段在 `MoveData.accentColor`，粒子数在 `sparkAmount`——**全部数据驱动，改表现不用动代码**。

### 1.7 招式身份与命名（2026-11-04）

| 字段 | 用途 | 怎么改 |
|------|------|--------|
| `MoveData.moveId` | **身份**：AI 读招、招式匹配、日志、未来的存档/回放都用它 | 改它 = 换一个招式身份；**换资源文件不用改它** |
| `MoveData.displayName` | 只给人看（日志 / HUD） | 随便改，不影响任何逻辑 |

**规则：**

1. **代码里不允许出现招式名字面量。** 一切"认招"都走 `moveId`。
2. **新增/替换招式 = 新建资源 + 填 `moveId`，不需要改代码。**
3. `moveId` 必须非空且互不重复——由断言 **A7** 守住（重复会让 AI 把两招当成同一招）。
4. 不单独建"映射表"：`moveId` 就写在每个招式资源里，**资源本身就是那张表**；再维护一份映射只会多一个失效点。

## 二、操作规格

### 2.1 键位（键鼠，暂不做手柄）

| 功能 | 键 | 备注 |
|------|----|------|
| 移动 | ← → | 只有左右；↑↓ 不参与移动（决策记录 2026-08-14） |
| **轻拳（jab）** | **Z** | 资源 / 招式名统一为 `test_light_punch` |
| **重拳（heavy）** | **X** | 资源 / 招式名统一为 `test_heavy_punch` |
| 脚键 | A / S | **暂时失效**（拳/脚区分押后，`InputManager` 不再采样） |
| 跳跃 | 空格 | 独立键 |
| 闪避 | Shift | **可穿过敌人身体**（2026-11-04） |
| 格挡 | C | 已绑定，M2 实现 |

> **决定（2026-11-04，你拍板）：轻/重由按键决定，不再由方向决定。**
> Z = 轻拳（`test_light_punch`），X = 重拳（`test_heavy_punch`）；**A / S 暂时失效**（拳/脚区分押后）。
> `→ + 攻击` 的方向选招与**搓招系统整体押后**，等出招表设计时再讨论（记入 `BACKLOG`）。
> **方向仍然只决定"朝哪打"**（`ResolveAttackFacing`），不决定"用哪招"。

> **决定（2026-11-04，你拍板）：暂不收敛，保留四键。**
> 你的原意是"轻拳 / 轻脚 / 重拳 / 重脚"。如果将来有**不同效果的搓招**需要区分拳脚，四键就有意义——现在砍掉等于提前关掉这条路。
>
> **收敛条件（写死）：** 若到 M2 结束，仍没有任何招式需要区分拳/脚（所有招只靠方向路由），
> 则收敛为"拳 / 脚"两键，轻重继续由方向决定。在此之前 `AttackType` 只做输入记录，**不参与选招**。

### 2.2 方向语义

- **绝对方向**：↑↓←→ 直接选招，不做"前/后"相对朝向的映射（无对手时的历史决策，现在敌人只在右/左侧，仍成立）。
- **出招朝向** = 出招瞬间按下的水平方向；无水平方向时沿用 `facing`（2026-11-04 修复）。
- **方向只决定"哪一招"，不决定"打多远"**——判定框始终朝向出招方向。

### 2.3 输入优先级（不可回退）

```
受击请求  >  闪避  >  顿帧闸门  >  普通 Tick
```

- 受击：请求化，下一帧立刻打断当前动作。
- 闪避：在顿帧闸门**之前**判定，所以顿帧期间也能闪。
- **例外**：闪避无敌期内被命中 → 命中无效（不触发受击）。

### 2.4 缓冲与容忍

| 机制 | 当前 | M1 目标 | 说明 |
|------|------|---------|------|
| 攻击缓冲 | ✅ 回扫 60 条输入日志 | 保持 | 顿帧/硬直期间按下的攻击不丢 |
| 跳跃缓冲 | ❌ 无 | ⏳ M2 | 落地前 6 帧按跳算数（需要平台内容才能验） |
| 土狼时间 | ❌ 无 | ⏳ M2 | 离开平台后 6 帧内仍可起跳 |
| 闪避缓冲 | ❌ 无 | 🔨 M1 评估 | 4 帧；当前只认当帧边缘 |
| 连段输入 | ✅ | 保持 | 招式结束瞬间取缓冲里的新边缘 |

### 2.5 已知输入缺陷

| 缺陷 | 影响 | 何时修 |
|------|------|--------|
| 硬直/顿帧期间的单帧攻击边缘被吞 | 玩家觉得"我按了没出招" | ⏳ M2（被读→硬直→回归节奏会最痛） |
| 闪避方向写死为 facing（`_dodgeDirection` 未用） | 不能"后撤步" | ⏳ M2 |
| 无手柄支持 | — | ❌ 不做（Demo 阶段） |

4. 闪避的"无敌"要能被**看见**（蓝 + 穿过攻击）。

## 四、敌人规格

> **设计铁律（2026-11-04 补）：没有安全区。**
> 玩家的出招距离必须落在敌人的威胁距离之内，否则最优解就是"站在范围外白嫖"（实测发生过）。
> 当前：玩家 jab 25–115；敌人普攻 0–110、解围 5–135 → 想打就一定会被威胁。

### 4.1 出题结构（每个敌人都一样）

```
Idle（白） → Startup（黄，出题） → Active（红） → Recovery（绿，破绽） → Idle
                    ↑                                          │
                    └────────── 被打断 / 识破 / 解围 ───────────┘
```

- **Startup 必须可读**：颜色 + 朝向在起手瞬间锁定，玩家据此决定躲还是确反。
- **Recovery 是给玩家的奖励窗口**：绿 = 安全确反。
- **被打断**：命中 → Hitstun（紫）→ Idle。*（当前"全可打断"，是教学敌人的设定，不是所有敌人的规则。）*

### 4.2 两种"读"（M1 新增第二种）

| 读法 | 触发条件 | 反应 | 玩家的应对 |
|------|---------|------|-----------|
| **名字读**（已有） | 同一招连续命中 **2 次** | 金常亮 + 霸体反打（**第 3 次同招被架住，0 伤害**） | 换招打穿 / 收手 |
| **压力读**（🔨 M1） | 压力条满 3 格时被命中 | 金闪烁 + 解围反击 | 收手 / 用 jab 骗后闪 |

**为什么必须有第二种：** 名字读只看 `_lastMoveId`，玩家 A/B 交替就能永久绕过——这是 2026-11-04 实测确认的免费解。**压力是绕不过去的维度。**

> **铁律（2026-11-04 补）：一次"架住"就是这一回合的结算，敌人不再挥第二刀。**
> 否则会出现**因果倒挂**：玩家被架住（-18）→ 敌人这刀打空 → 敌人踉跄 → 玩家白拿 ×3。
> 实现：`OnArmorPunishResolved()` —— 清预判、关判定框；前摇/判定中架住直接回 Idle（玩家仍在硬直，回合归敌人），
> 后摇中架住只清预判、不打断后摇（后摇是它应得的破绽）。
> 由此三选一才成立：**收手 → 它打空 → ×3；换招 → 打穿；同招 → 被架住吃 18、回合结束。**

### 4.3 压力 / 解围（M1 核心）

| 项 | 值 | 说明 |
|----|----|------|
| 压力条上限 | 3 格 | 敌人头顶显示 |
| 每被命中 | +1 格 | 不看招名 |
| 衰减 | 1 格 / 秒 | 让"收手"有收益 |
| 触发 | **第 3 次命中把条打满的那一刻** | 第 1、2 下安全；第 3 下危险 |
| 解围前摇 | 10 帧 | 金闪烁，可反应 |
| 解围伤害 | 10 | |
| 解围打空 | 进入 35 帧 Recovery | 玩家的奖励窗口（比普通后摇长） |

**三个选项（这就是 M1 要交付的"择"）：**

| 你的选择 | 结果 |
|---------|------|
| 条满时收手，等它掉格 | 安全，但少打一套 |
| 第三下用 **jab**，见金闪就闪 | 骗出解围 → 它扑空 → 你确反（正收益） |
| 第三下用 **heavy** | 躲不掉 → 吃一下（贪的代价） |

### 4.4 tell 语言

见 §1.6 色表。新增一条不变式：**同一颜色必须对应同一应对**。
- 金常亮 = 换招能打穿
- 金闪烁 = 换招也没用，只能躲

## 五、一局（遭遇）的结构

| 项 | 目标 |
|----|------|
| 形式 | 1 房间，玩家 vs 1 敌人，平地 |
| 时长 | **20–25 秒** |
| 判断次数 | 3–5 次（每次约 4–6 秒） |
| 玩家容错 | 8–10 下（HP 100 / 敌人 10 伤） |
| 击杀所需 | 约 20 次 jab 或 8 次 heavy 或混合 |
| 失败 | 玩家死亡 → 2 秒后重载（M1 先这样，M2 正式做死亡流程） |

**一局的节奏（目标体感）：**

```
0s   靠近，读起手 → 躲
3s   确反，打 2 下
5s   条满 2/3 → 判断：收手 or 贪第三下
8s   敌人再出题 → 躲/换招
12s  骗一次解围 → 它扑空 → 罚一套
18s  血量见底 → 收尾
22s  结束
```

## 九、调参顺序（只允许一次动一个）

1. **先看时长**：一局不在 20–25 秒 → 只调敌人 HP；
2. **再看判断次数**：一局少于 3 次判断 → 只调解围前摇/压力衰减；
3. **再看压力**：玩家总是被解围打死 → 先降解围伤害，再放宽前摇，**最后才动格数**；
4. **最后看数值**：伤害/气耗只在手感定型后调。
